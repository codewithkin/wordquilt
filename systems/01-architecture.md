# Architecture

## Shape

A pnpm + Turborepo monorepo, scaffolded by Better-T-Stack.

```
apps/
  native/          Expo SDK 57, expo-router, uniwind. THE PRODUCT.
  web/             Next.js. Not in launch scope — see below.
packages/
  tokens/          Design values as TypeScript. Mirrors apps/native/global.css.
  ui/              shadcn/React-DOM components. Web only. Not used by native.
  env/             Typed environment access.
  config/          Shared tsconfig base.
designs/           The design files, the extractor, and (gitignored) extracted values.
scripts/           Repo checks: assets, icons.
systems/ plans/ progress/    The working method. Tracked, not gitignored — see below.
```

### Launch scope is iOS + Android + store assets

`apps/web` and the website designs stay in the repo and are **not built yet**.
A marketing site with no traffic source is wasted effort at launch; the store
listing does that job. Do not spend session budget there.

### `plans/`, `systems/` and `progress/` are TRACKED

The workflow template suggests gitignoring them. We do not, deliberately
(D-001). Sessions here run in ephemeral cloud containers that are reclaimed
after inactivity — anything not committed is destroyed. Gitignoring the memory
would mean losing it every session, which defeats the entire method.

`designs/extracted/` IS gitignored: it is regenerated by `pnpm designs:extract`
in seconds and would otherwise add ~80k lines of noise to every diff.

## The token layer, and how it is kept honest

Values live in **two** places that cannot import each other:

- `packages/tokens/src/*.ts` — consumed by components as TypeScript
- `apps/native/global.css` — consumed by the uniwind/Tailwind compiler

Left alone these drift, and the failure is silent: both stay internally
consistent while one stops matching the design. Three checks span the gap.

| Check | Command | Catches |
| --- | --- | --- |
| Token parity | `pnpm check:tokens` | Any colour, radius, elevation, font or type role differing between the TS and the CSS. Also pins rules: no pure black/white, no error colour, no blurred shadow, no size/colour name collision. |
| Asset manifest | `pnpm check:assets` | Any shipped PNG whose size or alpha disagrees with the manifest **in the design file**, and any `app.json` key not pointing where the manifest says. |
| iOS icon alpha | `pnpm check:icons` | `expo prebuild` re-adding an alpha channel to the dark iOS icon, which App Store Connect rejects. |

Uniwind adds a fourth for free: it refuses to build if the `light` and `dark`
`@variant` blocks declare different variable sets.

All three checks have been deliberately made to fail and then restored. If you
add a check, do the same — a check written with a subtly broken pattern passes
forever because it matches nothing.

## Styling: how uniwind actually works here

Uniwind is Tailwind v4, CSS-first, compiled to React Native styles at build
time. There is no JS config file; **`apps/native/global.css` is the config.**

Theme variables are declared in `@variant light { }` / `@variant dark { }`
blocks inside `:root`, and exposed as utilities through `@theme inline static`.
Both themes must declare an identical set of variables.

### Two things that will bite you

1. **`shadow-*` vs the `wq-*` composites.** Tailwind's `shadow-card` compiles to
   a composed `var(--tw-inset-shadow), var(--tw-ring-shadow), …` chain. React
   Native's `boxShadow` parser takes a simple string, and the chain is not
   verified to survive it. The `wq-card` / `wq-tile` / `wq-button` composites
   emit a plain `box-shadow` and are the supported path (D-004). The token test
   enforces that they stay plain.

2. **Class names must be literal.** Uniwind extracts them statically at build
   time. A className built from a template string produces **no styles at all**,
   silently. Variant maps hold full literal strings for this reason.

### heroui-native

Installed and used for `cn` and a few primitives. Its semantic variables
(`--background`, `--surface`, `--accent`, `--border`, …) are **repointed at the
WordQuilt palette** in `global.css`. Without that repoint its components render
in the library's stock grey/blue while everything we build renders in
terracotta — self-consistent and completely wrong.

Verified: an iOS bundle contains every WordQuilt hex and **zero** occurrences of
heroui's stock accent.

## Fonts

Newsreader (display, italic only) and Nunito (UI), via `@expo-google-fonts`,
loaded in `app/_layout.tsx` behind the splash screen.

**One family per weight.** React Native does not synthesise weights for custom
families — `fontFamily: "Nunito"` with `fontWeight: 800` renders the regular cut
on Android and a faked bold on iOS. So each weight is a separately loaded face
whose key IS its family name, and **nothing in the app sets `fontWeight`.**
There is no font-weight token, and the token test asserts none appears.

Seven faces, verified present in an iOS bundle by content hash.

## Native project generation

`ios/` and `android/` are generated by `expo prebuild` and gitignored.
`app.json` is the source of truth.

`pnpm --filter native prebuild` runs prebuild **and then** the icon flattener,
because prebuild reintroduces the alpha channel every time.

### Not yet decided: the bundle identifier

`app.json` deliberately carries **no** `ios.bundleIdentifier` or
`android.package`. Prebuild defaults them to `com.anonymous.wordquilt`, which is
Expo's "you must change this" placeholder. These are permanent once submitted to
either store and are the owner's decision. **This is a launch blocker.**
